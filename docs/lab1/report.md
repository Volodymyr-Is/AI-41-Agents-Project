# Звіт про виконання Лабораторної роботи 1

## Що ми мали (Початковий стан)
- Шаблон проєкту з базовими налаштуваннями TypeScript, Next.js (App Router), Vitest.
- Налаштовані команди для лінтера, перевірки типів (`typecheck`) та модульного тестування.
- Доступ до двох агентів кодування (наприклад, Antigravity IDE та інший CLI-інструмент) для експериментів та паралельного вирішення задач.

## Що ми зробили
1. **Налаштування середовища та правил:** 
   - Створили стислий та ефективний файл `AGENTS.md` (до 200 рядків) із жорсткими правилами роботи для агентів.
   - Вказали заборони на редагування та читання файлів із секретами (`.env`, `.env.local`), обмежили деструктивні `git` команди.
   - Підключили `AGENTS.md` через `CLAUDE.md`, щоб усі агенти відразу отримували правильний контекст.
2. **Журналювання (Autonomy Log) та Безпека:** 
   - Запровадили ведення журналу сесій у директорії `.agent-log/` (`*.jsonl`), щоб фіксувати дії агентів (без витоку секретних даних у `input` інструментів). 
   - Налаштували хук заборони (`guard-env.mjs`), який перехоплює спроби агентів доступитись до середовищних змінних і відразу завершує процес із помилкою.
3. **Реалізація API та перевірка агентів:**
   - Реалізували простий ендпоінт `GET /api/health` за допомогою двох різних інструментів у різних гілках (`lab1/health-*`).
   - Написали Zod-схему (контракт) та тести (Vitest) до того, як віддали агентам задачу на реалізацію, забезпечивши принцип Test-Driven Development (TDD).
4. **Створення навичок (Skills):** 
   - Розробили навичку `add-api-route` згідно зі специфікацією `agentskills.io`.
   - Переконалися, що вона розпізнається та працює в обох агентах, провели тести на її спрацювання (позитивні та негативні сценарії).
5. **Вимірювання вартості та токенізації:** 
   - Виконали вимірювання витрат токенів та затримок на хмарній моделі, шлюзі (OpenRouter) та локальній моделі (Ollama).
   - Підтвердили дію кешування токенів (Prompt Caching) та виміряли різницю у вартості між англійською та українською мовами (кирилиця коштує значно дорожче через особливості BPE-токенізації).
6. **Розробка та перевірка агентних циклів:**
   - **Кастомний цикл (`agent-loop.ts`):** Реалізували власний цикл роботи агента з лімітами на кількість кроків (`maxSteps`) та бюджет токенів (`tokenBudget`), із валідацією JSON через Zod. Написали тести із моканням (без мережі) для перевірки зупинки на лімітах.
   - **AI SDK цикл (`agent-aisdk.ts`):** Використали пакет `ai` (AI SDK 7) для реалізації циклу із Human-in-the-Loop: налаштували переривання циклу та запит у користувача на підтвердження дії під час виклику інструменту `write_file` (`toolApproval`).
7. **Деплой та трасування:** 
   - Додали новий ендпоінт `/api/agent` для виклику агента через мережу.
   - Налаштували трасування через Langfuse для відстеження витрат токенів та затримок у продакшені.

## Як це працює
- **Безпека:** Хук заборони перехоплює наміри виклику інструментів (PreToolUse події). Якщо агент намагається прочитати або змінити `.env` або викликати заборонені bash-команди, процес переривається із результатом `"denied"`, і дія не виконується на файловій системі.
- **Агентний Цикл:** Агент працює у циклі `Виклик моделі -> Виклик інструменту -> Отримання результату -> Повтор`. Якщо модель не викликає жодного інструменту, від неї очікується фінальний JSON. На кожному кроці суворо перевіряються ліміти кроків та токенів, що унеможливлює неконтрольовані витрати грошей.
- **Тестування («Брами якості»):** Усі ключові компоненти покриті тестами без використання мережі (завдяки підміні викликів до моделей). Це дозволяє гарантувати, що логіка зупинки працює завжди коректно. Відповідність критерію «Готово, коли» забезпечується тим, що «поганий патч» гарантовано зробить ці надійні перевірки червоними.
