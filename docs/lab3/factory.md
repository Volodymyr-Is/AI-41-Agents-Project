- **Дата:** 2026-10-27 · **репозиторій:** [GitHub: Volodymyr-Is/AI-41-Agents-Project](https://github.com/Volodymyr-Is/AI-41-Agents-Project)
- **Шлях агента:** OpenRouter API runner (`scripts/harness/openrouter-agent.ts`, безкоштовні моделі `google/gemma-4-31b-it:free`) або Gemini CLI (`gemini`, модель `gemini-2.5-flash`)
- **Чому саме цей:** Повністю безкоштовний шлях виконання за специфікацією курсу через OpenRouter Free Tier / Google AI Studio (вартість $0.00). Не вимагає платної підписки Claude Console або платних кредитів OpenAI.
- **Режим дозволів:** `dontAsk` разом із явним переліком дозволених інструментів `--allowedTools "Read,Edit,Bash(npm test *),Bash(npm run typecheck *),Bash(git diff *)"`. Усі інші дії безумовно відхиляються.

## 1. Форма задачі

Черга задач зберігається у файлі [docs/lab3/tasks.jsonl](tasks.jsonl). Загалом сформовано 6 детермінованих задач для спортивного щоденника.

| Поле | Тип | Опис та семантика |
|---|---|---|
| `id` | `string` | Унікальний ідентифікатор задачі (`t-01` … `t-06`) |
| `input` | `string` | Однозначна інструкція для агента: які файли створити/змінити, які типи й функції реалізувати |
| `acceptance` | `string[]` | Масив shell-команд машинного контролю успіху (наприклад `["npm run typecheck", "npm test -- tests/..."]`) |
| `budget.max_turns` | `number` | Максимальна кількість кроків/ходів агента на задачу |
| `budget.max_usd` | `number` | Граничний бюджет вартості викликів у доларах США ($0.0 для Free Tier) |
| `budget.timeout_s` | `number` | Жорсткий таймаут виконання задачі у секундах (після якого процес завершується за ETIMEDOUT) |
| `files` | `string[]` | Явний список файлів, з якими агенту дозволено працювати |

## 2. Виклик агента

Агент викликається у неінтерактивному (headless) режимі без графічного інтерфейсу та без очікування ручного вводу користувача:

```bash
# 1. Шлях OpenRouter (працює локально через TypeScript-агента харнеса)
npx tsx --env-file=.env.local scripts/harness/run-queue.ts docs/lab3/tasks.jsonl --id t-01 --runner openrouter

# 2. Безкоштовний шлях Gemini CLI (-p форсує неінтерактивний режим, -o json генерує машинний вивід)
gemini -p "<input задачі>" -o json > runs/<task-id>/agent.json

# 3. Альтернативний шлях Claude Code (режим dontAsk із суворим бюджетом)
claude -p "<input задачі>" \
  --output-format json \
  --allowedTools "Read,Edit,Bash(npm test *),Bash(npm run typecheck *),Bash(git diff *)" \
  --permission-mode dontAsk \
  --max-turns 10 \
  --max-budget-usd 0.00 > runs/<task-id>/agent.json
```

## 3. Де лежать артефакти

- **Сирі робочі теки:** `runs/<id>-<timestamp>/` (додані в `.gitignore`, на диск пишуться тимчасово).
- **Збережені артефакти в репозиторії:** `docs/lab3/runs/<id>-<timestamp>/`.
- **Фактичний верифікований прогін задачі t-01:** [`docs/lab3/runs/t-01-1793125614234/`](runs/t-01-1793125614234/) (`exit_status: ok`, `acceptance_passed: true`, `npm run typecheck: 0`, `npm test: 0`, вартість $0.00).

Кожен успішний чи неуспішний прогін гарантовано створює **4 файли-докази**:
1. `patch.diff` — повний дифф створених/змінених файлів (отриманий через `git add -A && git diff --cached` у дереві задачі).
2. `output.txt` — потік стандартного виводу агента (`stdout`).
3. `agent.log` — потік помилок та логів середовища (`stderr`).
4. `run.json` — структурований журнал прогону.


---

## 4. Журнал прогону

Структура об'єкта `run.json`:

| Поле | Джерело значення |
|---|---|
| `task_id` | Значення `id` із черги `tasks.jsonl` |
| `agent_path` | Ідентифікатор використаного раннера агента (`gemini-cli`) |
| `artifact_dir` | Абсолютний або відносний шлях до каталогу артефактів — прямий зв'язок журналу з доказами |
| `started_at` / `ended_at` | Мітки точного часу початку та завершення прогону (ISO 8601) |
| `duration_s` | Точна тривалість виконання задачі у секундах |
| `exit_status` | Фінальний статус: `ok` (успішно), `agent_failed` (код помилки), `timeout` (перевищено час) або `budget_or_turns` |
| `acceptance` | Масив пар `{ cmd, exit }` для кожної команди приймання |
| `acceptance_passed` | `true`, якщо всі команди `acceptance` завершилися з кодом 0 |
| `session_id` | Ідентифікатор сесії з JSON-виводу агента (або `null`) |
| `input_tokens` / `output_tokens` | Кількість токенів із секції `usage` (або `null`) |
| `cost_usd_estimate` | Клієнтська оцінка вартості прогону ($0.00 для безкоштовного шляху) |
| `trace_id` | Трасувальний ідентифікатор OpenTelemetry (резерв під Крок 06) |
| `gates` | Статуси детермінованих перевірок (резерв під Крок 01) |

## 5. Як перезапустити одну задачу

Повторюваність гарантується можливістю перезапуску окремої задачі за прапорцем `--id`:

```bash
# Перезапуск задачі t-01 з черги
npx tsx scripts/harness/run-queue.ts docs/lab3/tasks.jsonl --id t-01

# Перевірка згенерованого журналу у PowerShell
Get-ChildItem runs -Filter run.json -Recurse | Where-Object { $_.FullName -match 't-01' } | Sort-Object LastWriteTime -Descending
```

Кожен запуск формує нову папку з міткою часу і не перезаписує історію попередніх прогонів.

## 6. Що перевірено без мережі

У файлі [tests/harness/run-task.test.ts](../../tests/harness/run-task.test.ts) реалізовано набір модульних тестів на базі Vitest без мережевих викликів:
- **Запис журналу та артефактів:** Перевірено, що `runTask` із підставним раннером створює повний комплект файлів і коректно рахує тривалість і статус `ok`.
- **Обробка падіння агента:** Перевірено, що при ненульовому коді виходу статус позначається як `agent_failed`, а в `agent.log` записується стек помилки.
- **Розпізнавання вичерпаного бюджету:** Перевірено відрізнення повідомлення про вичерпання бюджету від системного збою (`budget_or_turns`).
- **Стійкість до таймаутів:** Перевірено коректну фіксацію статусу `timeout` при перериванні процесу за лімітом часу.
- **Стійкість до непарсибельного виводу:** Перевірено, що некоректний JSON у stdout не ламає формування звіту, а записує `null` у поля метаданих.
