# Звіт Кроку 05: Мультимодальність у продукті

## 1. Роль мультимодальності у спортивному журналі

> **Формулювання ролі продукту:**  
> Фото або скан щоденника тренувань чи PDF-протокол бігового плану → розпізнавання виконаних вправ і розрахунок обсягу навантаження з генерацією аудіо-підсумку (TTS) для спортсмена, а при непридатному файлі — миттєве зрозуміле повідомлення про помилку.

### 1.1 Що робить застосунок, коли файл непридатний
Якщо файл непридатний для обробки, застосунок не падає з необробленим винятком (500 Internal Server Error) і не повертає технічний код помилки платформи (413 Function Payload Too Large). Натомість реалізованоfail-safe валідацію:
1. **Порожній файл (0 байтів)**: повертає код `EMPTY_FILE` та підказку: *«Будь ласка, оберіть непорожнє фото або скан тренувального щоденника.»*
2. **Перевищення ліміту розміру**: повертає `PAYLOAD_TOO_LARGE` або `CLIENT_ENCODED_TOO_LARGE` із поясненням та порадою стиснути фото або оптимізувати PDF.
3. **Непідтримуваний або підроблений MIME-тип**: повертає `UNSUPPORTED_MEDIA_TYPE` чи `MIME_TYPE_SPOOFED` із чітким переліком дозволених форматів (PNG, JPEG, PDF).
4. **Неякісне або розмите зображення**: здійснює часткове вилучення доступних даних та супроводжує відповідь попередженням (`warning`): *«Зображення має низьку контрастність або розмитий почерк. Частину повторень розпізнано наближено.»*
5. **Нерелевантний вміст (не тренування)**: повертає `NON_FITNESS_CONTENT` із вказівкою завантажити саме спортивні записи або тренувальний протокол.

## 2. Твердження щодо генерації зображень

> **Генерація зображень у крок 05 не входить, оскільки у перевірених джерелах курсу всі моделі зображень Gemini API на безкоштовному рівні мають статус «Not available».**  
> Дослідження офіційної сторінки тарифів Google Gemini API підтверджує, що моделі генерації зображень (`gemini-2.5-flash-image`, `gemini-3-pro-image`, `gemini-3.1-flash-image` тощо) та генерації відео (`veo-3.1-*`) не мають доступного Free Tier. Хоча AI SDK 7 надає функцію `generateImage`, її виклик неможливо виконати за нульову вартість, тому в продукті реалізовано виключно мультимодальний вхід (зображення/PDF) та аудіо-вихід (TTS).

## 3. Архітектура мультимодального входу (AI SDK 7)

### 3.1 Канонічна частина `FilePart` замість застарілого `ImagePart`
У попередніх версіях SDK використовувалася частина `{ type: 'image', image: ... }`. В `ai@7.0.118` інтерфейс `ImagePart` офіційно позначено як `@deprecated` із прямою заміною на `FilePart`.
У проєкті використовується виключно канонічний `FilePart`:
```typescript
export interface CanonicalFilePart {
  readonly type: 'file';
  readonly mediaType: 'image/png' | 'image/jpeg' | 'application/pdf';
  readonly data: {
    readonly type: 'data';
    readonly data: Buffer | Uint8Array | string;
  };
  readonly filename?: string;
}
```

### 3.2 Дворівнева перевірка лімітів розміру (платформа vs base64)
- **Серверний ліміт платформи**: Vercel Serverless Function має жорстку межу на тіло запиту — **4.5 MB** (4 718 592 байти). Якщо надіслати запит понад цей розмір, Vercel повертає `413 FUNCTION_PAYLOAD_TOO_LARGE` ще до виконання коду функції.
- **Оверхед Base64**: передача бінарного файлу через JSON у кодуванні base64 додає близько 33.3% оверхеду (4 символи на кожні 3 байти).
- **Клієнтський поріг**: для файлу розміром 3.5 MB закодоване тіло перевищить 4.6 MB і спричинить падіння. Тому в коді [`src/multimodal/types.ts`](file:///c:/Users/volod/OneDrive/Документи/GitHub/AI-41-Agents-Project/src/multimodal/types.ts) визначено константу `CLIENT_RAW_MAX_BYTES = 3 538 944` (~3.37 MB) та реалізовано попередню клієнтську перевірку перед формуванням запиту.

### 3.3 Захист від MIME-спуфінгу (Magic Bytes)
Щоб уникнути помилок при обробці файлів, розширення яких було змінено вручну або підроблено клієнтом (наприклад, текстовий файл або двійковий файл перейменовано на `.png`), функція `detectMagicMediaType` перевіряє перші байти сигнатури файлу:
- **PNG**: `89 50 4E 47 0D 0A 1A 0A`
- **JPEG**: `FF D8 FF`
- **PDF**: `%PDF-` (`0x25, 0x50, 0x44, 0x46, 0x2D`)
Якщо заявлений клієнтом заголовок не збігається з сигнатурою, запит блокується з кодом `MIME_TYPE_SPOOFED`.

## 4. Мультимодальний вихід: Синтез мовлення (Free Tier TTS)

Для озвучення результатів аналізу тренування використовується аудіо-вихід (TTS).
- **Вибір моделі**: `gemini-2.5-flash-tts` на безкоштовному тарифі Free Tier.
- **Запобігання платним моделям**: у модулі [`src/multimodal/processor.ts`](file:///c:/Users/volod/OneDrive/Документи/GitHub/AI-41-Agents-Project/src/multimodal/processor.ts) реалізовано запобіжник, який блокує будь-які запити до `gemini-2.5-pro-preview-tts` (модель Pro Preview є платною з першого ж токена).
- **Формат**: `audio/mp3`, голос за замовчуванням `Fenrir` або `Puck`, динамічний розрахунок орієнтовної тривалості звучання.
